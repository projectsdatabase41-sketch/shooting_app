# Безопасность Nexus: аудит и план (2026-10-20)

Nexus хранит токены входа, ключи ИИ, пароль моста Google Диска, историю чатов. Ниже — что сделано, где остаются риски и что планируется. Не выдумано: всё из кода репозитория.

## Сделано
- **Секреты в локальной базе зашифрованы** (`lib/services/secret_box.dart`): AES-256-GCM, ключ лежит в Android Keystore / iOS Keychain (`flutter_secure_storage`), в SQLite его нет. Зашифрованы: токены входа в личную базу и в мессенджер (`auth_*`, `chat_*`), токен доступа тренера, ключи ИИ (`ai_api_key`, `ai_gemini_key`), пароль моста Google Диска. Старые значения шифруются при запуске (`SecretBox.migrate`). Если защищённое хранилище недоступно — работает как раньше (без шифрования).
- **Android: `allowBackup=false`** — база приложения не уходит в резервные копии Google/adb.
- **Мост Google Диска:** пароль генерирует приложение (32 символа), проверка пароля в скрипте, замедление подбора (пауза 1,5 с при неверном пароле).
- База Supabase: все таблицы только для владельца (RLS), роль anon доступа не имеет (проверяется в «Проверке базы»).

## Открытые риски (по убыванию важности)
1. **`project_settings.chat_password`** — пароль мессенджера лежит в личной базе открытым текстом (для тихого входа с других устройств). Защищён RLS (видит только владелец), но пароль в хранилище — плохая практика. План: убрать, входить по refresh-токену, пароль не хранить.
2. **Папка `Nexus/Chats` на телефоне** — файлы и история чатов лежат открыто в общей памяти; прочитать их может любое приложение с доступом «ко всем файлам». План: шифровать папку паролем пользователя (или ключом из Keystore + запасной пароль для восстановления после переустановки).
3. **Веб-версия:** токены и ключи хранятся в браузере (IndexedDB/localStorage); шифрование ключом из браузера защитой от XSS или чужого доступа к профилю не является. План: на вебе короткие сессии, не хранить долгоживущие ключи ИИ.
4. **Ключи, вшитые при сборке** (`OPENROUTER_KEY*` через `--dart-define`) можно достать из APK. План: прокси на сервере с лимитами вместо ключа в приложении.
5. **Мост Google Диска:** пароль даёт полный доступ к Диску (включая удаление). План: второй пароль «только чтение» и ограничение одной папкой (для ИИ и витрины), ротация пароля, журнал вызовов в скрипте.
6. **Локальная база целиком** (тренировки, чаты) не зашифрована — только секреты. План: SQLCipher (дороже по размеру и совместимости), решать отдельно.
7. **Вход в приложение:** нет блокировки PIN/отпечатком. План: опциональная блокировка при запуске.

## Правила на будущее
- Любой новый секрет (ключ, токен, пароль) хранить только через `SecretBox` (колонка в `SecretBox.settingsColumns` или ключ в `SecretBox.prefKeys`).
- Секреты не писать в логи, отзывы об ошибках и тексты исключений.
- Не публиковать адрес и пароль моста; при утечке — сменить `SECRET` в скрипте и выпустить новую версию развёртывания.
- Ключ `service_role` Supabase никогда не использовать в приложении и не передавать ИИ.
