# Публичная страница просмотра финала (web/final.html)

Владелец 24.11: «Публичные финалы и возможности просмотра их в реальном времени +
трансляция финалов» — ответ «Без видео». Страница read-only: только GET табло,
RPC `finals_board_join` и прослушивание Broadcast realtime. Никаких записей в базу,
никаких токенов пользователя в URL и интерфейсе; anon-ключ — публичный
(`sb_publishable_*`), тот же, что носит само приложение.

## Как страница получает канал

1. Адрес `final.html?id=<uuid финала>` (синоним `?board=<uuid>`).
2. Заголовок и статус берутся GET-ом с табло `finals_board`
   (колонки `host_name, region, format_id, people, top` — публичные, см.
   `sql/finals-board.sql`).
3. RPC `finals_board_join` возвращает `{key, url, anon_key}`:
   - `key` — секретное имя канала (полный топик `realtime:final:<key>`);
   - `url`/`anon_key` — база ведущего, если финал идёт в его личном Supabase
     (иначе страница использует константы ниже, те же, что у приложения).
4. Открывается WebSocket `wss://<host>/realtime/v1/websocket?apikey=…&vsn=1.0.0`,
   канал `realtime:final:<key>` с `config.broadcast {self:false, ack:false}`,
   `private:false` и `access_token` = anon-ключ — ровно как у зрителя приложения
   (`FinalsSessionService.publicChannel`, `lib/finals/finals_session_service.dart`).
5. После входа страница один раз шлёт `hello` (как `FinalsGuest.hello()`), хозяин
   в ответ рассылает свежий снимок — дальше слушаем событие `state`
   (`FinalsHost.broadcast`, `lib/finals/finals_net.dart`). Токен зрителя
   генерируется на месте (`web-…`, длина больше 16 — хозяин засчитывает его
   зрителем, пока есть места: `finals_invite.dart → accept`).

Единственное место с адресом и ключом — константы в начале `web/final.html`
(`DEFAULT_BOARD_URL`, `DEFAULT_BOARD_ANON`). Они повторяют значения из
`lib/services/chat_settings.dart` и `config/chat-config.json` (`chat.url`,
`chat.anonKey`): при смене базы мессенджером обновить их в трёх местах.

## Какие поля снимка `state` рисуются

- Заголовок: название финала (с табло), фаза `phase` (sighting/loading/
  shooting/grace/finished), подпись раунда `round` (`series:N`, `single:N`,
  для `rifle_3p_50m` — положение), таймер: `left` секунды, доматывается
  локально между пакетами; пауза — плашка с `pb` (кто) и `pn` (причина/лимит
  пауз ISSF 2026).
- Таблица: `place`, `no` (стартовый номер), `name`, `total`, `avg`, число
  выстрелов `shots`; выбывший (`active:false`) — приглушён.
- «Центральные»: колонка X и счётчик «Σ … — N» — считаются геометрически из
  точек `pts` по порогам мишени (`logic/scoring.dart → _innerTenSpecs`):
  № 8 — 2.00 мм, № 7 — 5.30, № 9 — 4.75, № 4 — 15.30, № 15/16 — 28.81.
  Для мишеней без критерия вместо N — прочерк.
- Мишени: SVG-сетка по всем строкам; кольца — официальные диаметры из
  `target_face.dart`, масштаб — по радиусу бланка (владелец 24.11 для № 7 и
  винтовок 10 м); чёрное яблоко, внутренняя десятка пунктиром, точки `pts`,
  последняя выделена и подписана целой оценкой (десятые доли снимок зрителя
  не содержит). Неизвестный код мишени — универсальная зона по дальней
  пробоине; целочисленные и «попал/мимо» мишени рисуются одной зоной.
- Событие `ended` — плашка «Финал окончен»; `denied` (нет мест/не позвали) —
  сообщение и остановка переподключения.

## Без id и при обрыве

- Без id: список живых финалов (`status='live'`, не старше 6 часов — это RLS
  табло), обновление каждые 20 секунд, ссылки на `final.html?id=…`. Сетевых
  подключений к каналам в этом режиме нет.
- Обрыв WebSocket: плашка «нет связи», переподключение с удвоением паузы
  1→15 с; каждое переподключение заново проходит через RPC join (заодно
  отслеживает переход финала в finished).
- `finals_board_join` вернул пусто (финал окончен/убран) — «Финал уже
  недоступен» и ссылка на список.
- Если ошибка сети и при списке — плашка «Нет связи с табло», список
  обновится сам.

## Приватность и деплой

- Ключи и имя канала нигде не выводятся и не логируются.
- Файл самодостаточен (без CDN) и работает на GitHub Pages вместе с остальной
  папкой `web/`. Страница статична: `web/final.html` (+ этот документ).

## Что осталось (не блокирует просмотр)

- Десятые доли последнего выстрела и суммы серий (`S1 … · S2 …`) в подписи под
  мишенью — в снимке зрителя их нет; появится, если хозяин начнёт класть в
  снимок готовые оценки (`shots` приходят только по завершении финала).
- Пристрелочные выстрелы ботов в снимок не попадают (`sightShots` идут мимо
  `shots`), поэтому мишень во время пристрелки пустая — это совпадает с
  приложением.
