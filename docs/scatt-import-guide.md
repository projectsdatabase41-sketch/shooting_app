# Как записать отчёты SCATT в базу, чтобы они появились в истории тренировок

Инструкция для того, кто пишет данные в базу НАПРЯМУЮ (не через
приложение) — например, разбирая PDF-отчёты SCATT Expert или другой
источник результатов. После записи по этой схеме тренировка появится
в истории спортсмена при обычной синхронизации (Настройки →
Синхронизировать сейчас), без каких-либо изменений в приложении.

Схема базы и общая таблица соответствия полей — `docs/db-schema-actual.md`.
Здесь — то же самое, но применительно конкретно к разбору отчёта SCATT.

## 0. Что даёт отчёт SCATT и чего в нём нет

Даёт на каждый выстрел: результат (например `10.6`), направление
восьмью секторами (стрелка ↑↗→↘↓↙←↖, либо пунктирный кружок — почти
идеально в центре, направления нет), время прицеливания, устойчивость
(Z2/Z2+), скорость подвода. Заголовок отчёта — спортсмен, дата/время,
оружие, дистанция, калибр.

**Не даёт**: точные координаты X/Y пробоины в мм. Их придётся
восстановить обратным пересчётом из результата и направления (раздел
2 ниже) — это приближение, не то, что дал бы реальный электронный
тренажёр с прямым выводом координат, но для отображения группы и
статистики этого достаточно.

## 1. Порядок записи (важен из-за внешних ключей)

1. `target_faces` — найти подходящую строку по `code` (см. таблицу
   ниже), запомнить её `id`.
2. `exercise_templates` — найти существующую строку по совпадению
   `name` + `target_face_id` + `shots_per_series`; если нет — завести
   новую. **Не плодить новую строку на каждый файл** — один и тот же
   вид упражнения должен переиспользоваться между тренировками, как
   это делает и само приложение.
3. `training_packages` — новая строка, одна на файл/сессию.
4. `exercises` (это СНИМОК исполнения упражнения внутри пакета, не
   каталог — см. `docs/db-schema-actual.md`) — новая строка, одна на
   пакет, с явной ссылкой на шаблон из шага 2 через `extra.template_id`
   (см. раздел 4 — без неё приложение при синхронизации не свяжет
   тренировку с нужным упражнением и заведёт локально дубликат).
5. `shots` — по одной строке на выстрел.
6. `comments` — по желанию, см. раздел 6.

## 2. Мишень и обратный пересчёт координат по результату+направлению

| Оружие в PDF | Дистанция/калибр в PDF | `target_faces.code` |
|---|---|---|
| Пневматическая винтовка | 10 m / 4.5 mm | `rifle_10m` |
| Пневматический пистолет | 10 m / 4.5 mm | `pistol_10m` |
| Малокалиберная винтовка | 50 m / 5.6 mm | `rifle_50m` |
| Пистолет | 25 m / 5.6 mm | `pistol_25m` |

Геометрия каждой мишени (радиусы границ колец в мм, от 10 до 1; шаг
одной десятой; радиус пули):

| code | границы колец 10..1, мм | шаг десятой, мм | радиус пули, мм |
|---|---|---|---|
| `rifle_10m` | 0.25, 2.75, 5.25, 7.75, 10.25, 12.75, 15.25, 17.75, 20.25, 22.75 | 0.25 | 2.25 |
| `rifle_50m` | 5.2, 13.2, 21.2, 29.2, 37.2, 45.2, 53.2, 61.2, 69.2, 77.2 | 0.8 | 2.8 |

(Для пистолетных мишеней — `pistol_10m`/`pistol_25m` — те же величины
есть в `lib/models/target_face.dart`, если понадобятся.)

**Шаг 1 — расстояние от центра по результату.** Результат вида
`ring.decimal` (например `10` и `6` из `10.6`):

```
index    = 10 - ring                         # 0 для десятки, 9 для единицы
r_calc   = граница_кольца[index] - (decimal + 0.5) * шаг_десятой
distance = r_calc + радиус_пули              # ОБЯЗАТЕЛЬНО прибавить, не вычесть
if distance < 0: distance = 0
```

Проверка на контрольном примере (`rifle_50m`, результат `10.6`):
`index=0`, `граница=5.2`, `r_calc = 5.2 - 1.1 = 4.1`,
`distance = 4.1 + 2.8 = 6.9` мм от центра — совпадает с проверочной
таблицей в `lib/logic/scoring.dart`.

**Шаг 2 — угол по стрелке компаса** (0° = вверх, дальше по часовой
стрелке — та же система, что и в самом приложении):

| стрелка | ↑ | ↗ | → | ↘ | ↓ | ↙ | ← | ↖ | пунктирный кружок |
|---|---|---|---|---|---|---|---|---|---|
| угол | 0° | 45° | 90° | 135° | 180° | 225° | 270° | 315° | направления нет |

Для пунктирного кружка (выстрел почти точно в центре) — `distance` из
шага 1 и `x_mm = y_mm = 0`, угол не нужен.

**Шаг 3 — координаты:**

```
x_mm = distance * sin(угол в радианах)
y_mm = distance * cos(угол в радианах)
```

## 3. `training_packages` — одна строка на файл

| Колонка | Откуда в PDF |
|---|---|
| `started_at` | дата+время из заголовка («26.06.2023 12:37») |
| `ended_at` | `started_at` + «Общее время» |
| `time_is_approximate` | `true` — время восстановлено из отчёта, не записано живьём |
| `package_status` | `'completed'` (слова `'finished'` в базе не существует — CHECK пропускает только `draft`/`active`/`completed`/`archived`) |
| `title`, `note` | необязательно; если это соревнование — коротко указать в `note` (например «Чемпионат области»). **Важно:** на сегодняшний день приложение эти два поля при синхронизации не читает вообще (см. предупреждение в конце файла) — писать можно про запас, но в интерфейсе спортсмена это пока не появится. |
| `editor_mode` | `'athlete'` |
| `is_locked_by_athlete` | `true` |
| `local_version` | `1` |

## 4. `exercises` (снимок исполнения) — одна строка на файл

| Колонка | Откуда |
|---|---|
| `id` | **тот же uuid**, что у строки `training_packages` из раздела 3 (так делает и сам мост приложения — отдельный id дочерней строке не нужен) |
| `package_id` | id этой же `training_packages` |
| `exercise_name` | название упражнения, см. раздел 5 |
| `discipline` | `target_faces.code` |
| `distance_meters` | 10, 25 или 50, из заголовка PDF |
| `target_face_id` | id из раздела 2 |
| `decimal_scoring` | `true` |
| `expected_shots` | «Выстрелов: N» из отчёта |
| `started_at` | тот же, что у пакета |
| `time_is_approximate` | `true` |
| `extra` | `{"template_id": "<id exercise_templates из раздела 5>"}` — **без этого поля синхронизация не свяжет тренировку с существующим упражнением** |

## 5. `exercise_templates` — искать по имени+мишени+серии, заводить один раз

Имя упражнения — то, что должно повторяться между файлами одного вида
тренировки, например `"Пневматическая винтовка 10 м"` /
`"Малокалиберная винтовка 50 м"`. Перед вставкой ОБЯЗАТЕЛЬНО проверить,
нет ли уже такой строки (`name` + `target_face_id` + `shots_per_series`
совпадают) — если есть, использовать её `id`, не плодить копию.

| Колонка | Значение |
|---|---|
| `code` | любая уникальная техническая строка, например `scatt_rifle_10m` — нигде в интерфейсе не показывается |
| `name` | см. выше |
| `weapon_type` | `'rifle'` или `'pistol'` |
| `ammo_type` | `'air'` (4.5 mm) или `'smallbore'` (5.6 mm) |
| `distance_m` | 10/25/50 |
| `shots_count` | типичное число выстрелов на тренировку для этого вида (например 60) |
| `shots_per_series` | 10 (во всех виденных отчётах серия — 10 выстрелов) |
| `target_face_id` | id из раздела 2 |
| `is_custom` | `true` |
| `is_active` | `true` |

## 6. `shots` — по одной строке на выстрел

| Колонка | Откуда в таблице PDF |
|---|---|
| `id` | новый uuid |
| `exercise_id` | id строки `exercises` из раздела 4 (= id пакета) |
| `shot_no` | колонка `№` (сквозная нумерация 1..N по всей тренировке, не сбрасывается по сериям) |
| `series_no` | номер блока «Серия N», к которому относится строка |
| `x_mm`, `y_mm` | восстановленные в разделе 2 |
| `coordinate_source` | `'pdf'` (имя прибора в эту колонку не пишется — она знает только `tap`/`score_angle`/`file_import`/`pdf`/`photo`/`auto`/`manual_corrected`; отчёт SCATT — это `'pdf'`, а `"scatt"` живёт в `extra`, см. раздел 7) |
| `computed_score` | можно не заполнять |
| `final_score` | результат ИЗ ОТЧЁТА КАК ЕСТЬ (например `10.6`) — **не пересчитывать** по восстановленным координатам, отчёт — источник истины |
| `source` | `'pdf'` (та же причина — `'scatt'` среди допустимых значений нет) |
| `is_manually_corrected` | `false` |
| `confirmed` | `true` |
| `shot_time_ms` | **смещение в миллисекундах от начала тренировки** (тип `integer` — эпоха туда не влезает, час стрельбы даёт `22003 integer out of range`); точного времени каждого выстрела в отчёте нет, приемлемое приближение — накопленное среднее время на выстрел (колонка «На выстрел, среднее» в шапке) умноженное на номер выстрела |
| `counts` | `true`, ЕСЛИ ИЗВЕСТНО, что конкретная серия — пристрелочная (человек так скажет отдельно, в самом отчёте SCATT это никак не помечено) — `false` для всех выстрелов той серии |
| `extra` | показатели прибора на этот выстрел — раздел 7 |

## 7. `shots.extra` — показатели прибора, не пометка спортсмена

Отдельно от `comments` (это ручные заметки спортсмена/тренера,
`level='shot'`) — сюда идут ВЫЧИСЛЕННЫЕ приложением-тренажёром
характеристики, помеченные, что это данные прибора, а не чьё-то
мнение:

```json
{
  "scatt": {
    "aim_time_s": 18.4,
    "hold_10_5_pct": 35,
    "hold_10_5_relative_pct": 45,
    "speed_1s_mm_s": 23.2,
    "speed_0_25s_mm_s": 26.1
  }
}
```

Ключи внутри `"scatt"` — как в столбцах таблицы отчёта (время
прицеливания, устойчивость Z2/Z2+, скорость за 1с/0.25с). Вложенность
именно под ключом `"scatt"` — чтобы при чтении сразу было видно, что
это не произвольная заметка, а показатели конкретного прибора;
приложение (и ассистент, которому этот `extra` виден целиком) не
путает одно с другим.

## 8. `comments` — по желанию, для контекста тренировки

Если нужно что-то передать текстом (например «финал соревнований» или
особые обстоятельства) — можно добавить одну запись уровня `session`:

| Колонка | Значение |
|---|---|
| `package_id` | id пакета |
| `level` | `'session'` |
| `shot_id`, `series_no` | `null` |
| `author_role` | `'athlete'` |
| `text` | свободный текст |

Это, в отличие от `training_packages.note`, приложение уже показывает
— в разделе комментариев к тренировке на экране мишени.

## Известное ограничение (на сегодня)

`training_packages.title`/`note` синхронизация приложения пока не
читает — если для соревнований/описания тренировки нужно, чтобы это
было видно спортсмену в истории, лучше воспользоваться комментарием
уровня `session` (раздел 8) либо явно попросить добавить в приложение
чтение этих двух полей — это небольшая доработка.
