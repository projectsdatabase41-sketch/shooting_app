# Хранение переписок на Google Диске (формат для ИИ)

Отзыв 25.11 (`b2f77808`): в Supabase мало места на переписки, фото и файлы.
История и медиа теперь живут на личном Google Диске пользователя в папке
`Nexus/Chats` в формате, удобном для ИИ; Supabase используется только для
доставки новых сообщений (realtime/сеть не менялись).

Реализация: `lib/gdrive/chat_ai_export.dart` (класс `ChatAiExport`), настройки —
`lib/screens/chat_backup_settings_screen.dart`, ключ режима —
`chat_store_drive_only` в `color_prefs` (`ChatDriveBackup.driveOnlyOn`,
по умолчанию ВЫКЛ).

## Структура папок

```
Nexus/Chats/
  AI-README.md          — памятка для ИИ (пишется/обновляется при каждой выгрузке)
  <chatId>/             — одна переписка (id собеседника или группы)
    messages.jsonl      — вся история, по одному JSON-объекту на строку
    chat.md             — человекочитаемая версия (заголовок, участники, «[дата время] Имя: текст»)
    media/              — сами фото/видео/аудио/файлы
```

Вложения до 20 МБ (`ChatDriveBackup.maxFileBytes`). Имена файлов в `media/`
детерминированы `<время>_<id>_<имя>`, поэтому уже загруженные не перезаливаются.

## Поля messages.jsonl

| Поле | Тип | Смысл |
|---|---|---|
| `v` | int | версия формата, сейчас `1` |
| `id` | string | ключ сообщения (`client_message_id`), уникален в переписке |
| `chat` | string | id переписки (= имя папки) |
| `from` | string | id отправителя |
| `to` | string | id получателя (личный чат) или id группы |
| `ts` | string | ISO-8601 UTC, например `2025-11-21T14:03:00.000Z` |
| `kind` | string | `text` \| `photo` \| `video` \| `audio` \| `file` \| `call` \| `system` |
| `text` | string? | текст или подпись к вложению |
| `reply_to` | string? | короткая цитата сообщения, на которое отвечали |
| `file` | object? | `name`, `mime`, `size` (int, байты), `path` — путь внутри папки переписки (`media/…`); `path: null` — файла на Диске нет |

## Как читать (для ИИ)

- Ищите по `text` в `messages.jsonl` (grep работает: каждая запись — одна строка файла).
- Фильтруйте по `ts` лексикографически — ISO-8601 UTC сортируется как строка.
- Название типов (`kind`) и назначение полей описаны прямо в папке: `Nexus/Chats/AI-README.md` —
  он переписывается при каждой выгрузке, поэтому всегда актуален.
- Медиа открываются по `file.path` относительно папки переписки.

## Идемпотентность

`exportChat(chatId)` и `exportAll()`:

- пишут только сообщения, которых ещё нет в `messages.jsonl` (сверка по `id`);
- не перезаливают вложения, уже лежащие в `media/`;
- `chat.md` и `AI-README.md` перегенерируются целиком;
- выгруженные строки тут же дописываются и при повторном запуске не дублируются
  (чистые функции `aiExportedIds`/`aiAppendLines` покрыты тестами).

## Режим «Хранить переписки только на Google Диске»

`chat_store_drive_only` (`ChatDriveBackup.driveOnlyOn`), по умолчанию ВЫКЛ.
Когда включён:

- `ChatDriveBackup.runIfDue` после обычной копии запускает `ChatAiExport.exportAll()`;
- после успешного экспорта переписки её транзитные строки из `chat_messages`
  старше 7 дней удаляются через REST: `DELETE /rest/v1/chat_messages?created_at=lt.<момент>&or=(…)`,
  RLS-политика `chat_messages_delete` разрешает удалять только свои строки
  (`sender_id = я` или `recipient_id = я`) — чужие строки сервер не тронет
  (`ChatAiExport.cleanupSupabaseTransit`);
- свежие сообщения остаются в Supabase для доставки, таблица перестаёт расти;
- удаление не удалось — экспорт внутренне успешен, но в статусе выгрузки
  появляется понятная ошибка; данные не теряются (они на Диске и в локальной базе).

Замечания:

- старые медиа в `chat-backup`-хранилище личной базы Supabase (копия
  `ChatBackupService`) и осиротевшие объекты `chat-media` (получатель не забрал
  вложение за 7 дней) этим режимом не чистятся — это отдельная работа;
- строка, не забранная получателем за 7 дней, при включённом режиме
  удаляется и без доставки: сообщение, не дошедшее за неделю, считается потерянным.
