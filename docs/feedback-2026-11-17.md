## Что нужно от владельца (без этого звонки за NAT не заработают)

Сервер звонков (`cloud/calls-worker`) выдаёт TURN, только если в его секретах
есть Cloudflare TURN (`TURN_KEY_ID`, `TURN_KEY_API_TOKEN`) или Metered
(`METERED_ICE_URL`). Сейчас в отчётах `ice=stun,turn`, но relay-кандидатов нет,
то есть рабочий TURN не выдавался. Проверить и задать:

```powershell
cd cloud\calls-worker
npx wrangler login                       # токен Cloudflare протух
npx wrangler secret put TURN_KEY_ID
npx wrangler secret put TURN_KEY_API_TOKEN
npx wrangler deploy
```

Ключи выдаёт Cloudflare Dashboard → Realtime → TURN. После этого в отчёте о
сбое появится `turn=cloudflare relay:N` (или `turn=none` — значит TURN так и не
выдаётся), и по этому полю сразу видно, где обрывается.

## Бесплатных TURN больше нет (проверено 17.11)

`tool/turn_probe.mjs` делает настоящую TURN-аллокацию с MESSAGE-INTEGRITY, а не
просто STUN-запрос:

| Сервер | Результат |
|---|---|
| `openrelay.metered.ca` | домен = `192.0.2.1` (заглушка), таймаут |
| `freestun.net:3478` (free/free) | таймаут (сервер не отвечает) |
| `relay1.expressturn.com:3478` | живой TURN, но учётные данные выдаёт только по подписке |

Так что рассчитывать можно только на TURN, который выдаёт сервер звонков.
