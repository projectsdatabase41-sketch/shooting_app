# Автоимпорт моделей из Google Диска в R2 (27.11)

Владелец обновляет папку моделей на Диске — воркер дважды в день сам
переносит новые и изменённые `.stp` в приватный R2 и обновляет каталог.
Приложение берёт каталог с воркера (`/models/index`), поэтому новые модели
появляются без пересборки.

## Что нужно один раз

1. **Google Cloud** → создать проект → включить **Google Drive API** →
   Credentials → **Create credentials → Service account**. У сервисного
   аккаунта создать ключ **JSON** и скачать файл.
2. В Google Диске открыть папку моделей (`1jctM_rUtijeK3ts8lPUfRW5NSzT88VFO`)
   → «Поделиться» → добавить `client_email` из JSON-ключа с правом
   **«Читатель»** (Viewer).
3. Положить JSON сервисного аккаунта в секрет воркера:

```powershell
cd C:\Users\Admin\Downloads\shooting_app\cloud\calls-worker
npx wrangler secret put GOOGLE_SA_JSON
```

и вставить **весь JSON** одной строкой (wrangler попросит значение).

4. Задеплоить воркер:

```powershell
npx wrangler deploy
```

## Как работает

- Cron воркера: `0 4,16 * * *` (04:00 и 16:00 UTC — 09:00 и 21:00 по
  Екатеринбургу). После новостей и пробуждения Supabase запускается
  `syncModelsFromDrive`.
- Воркер обходит дерево папки, сверяет `md5` файлов с состоянием
  `models/sync.json` в R2 и переносит только новое/изменённое.
- Каждый `.stp` шифруется (`MODELS_KEY`) и кладётся в
  `models/<drive-id>/model.stp`; каталог `models/catalog.json`
  пересобирается и отдаётся как `/models/index`.
- Имена существующих моделей и порядок сохраняются; новая модель получает
  имя из файла, категорию — из первой подпапки.

## Ограничения

- За один запуск переносится не больше 60 файлов; остальное — следующим
  запуском (дважды в день).
- Файлы больше 64 МБ пропускаются с предупреждением в логах.
- Ничего не удаляется: убранные с Диска модели остаются в R2 и каталоге,
  пока их не убрать вручную.
- Если `GOOGLE_SA_JSON` не задан, синхронизация молча пропускается —
  остальной воркер работает как обычно.
- Сервисному аккаунту нужен доступ именно к папке (не «Мой диск» целиком).

## Проверка

После ближайшего запуска:

1. В Cloudflare → Workers → `pusl-calls` → Logs: строка `gdrive: перенесено
   N файлов`.
2. `GET https://pusl-calls.pusl-calls.workers.dev/models/index` — в списке
   появились новые `id`.
3. В приложении открыть 3D-каталог заново (перезапуск не обязателен, но
   каталог кэшируется в памяти экрана).
