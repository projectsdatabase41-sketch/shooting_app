# Финалы: аудит по 12 пунктам владельца и статус (24.11.2026)

Аудит выполнен локальным ИИ (Vibe) по коду `lib/finals`, `lib/screens/final*`,
`lib/services/*`; реализовано четыре среза. Коммиты `042fae2`, `29d218b`,
`7f1bd6c`, `395a868`.

## 1. Боты: привязка к тренировкам и сложности — СДЕЛАНО (частично)

- Новый режим **«Авто»** (по умолчанию): если по мишени и изготовке ≥20
  зачётных выстрелов — бот калибруется так, чтобы его средний результат
  совпадал со средним спортсмена (бисекция по детерминированной сетке).
- Если истории мало — берётся разряд из профиля (`UserProfile.rankOf`) и
  нормативная таблица `lib/finals/rank_norms.dart` (средний выстрел и σ по
  разрядам 3ю…МСМК для 10 м винтовка/пистолет и 50 м 3P).
- Изготовка берётся из названия упражнения («лёжа/стоя/колено»); для 3P —
  отдельный уровень на положение с поправками (лёжа ×0.75, колено ×1.0,
  стоя ×1.30).
- Ручной режим (мин/макс/средний/ТП/направление) остался как «свой уровень»,
  когда истории нет. В комнатном финале боты пока на старом «medium» —
  подключить «Авто» туда отдельным шагом.

**Что нужно подтвердить владельцу:** нормативные суммы (таблица собрана по
общеизвестным значениям, помечена «сверить с ЕВСК»).

## 2. Паузы ботов — СДЕЛАНО

Вместо плоской паузы — стадии «отдых → прицеливание → перезарядка → выстрел»:
винтовка 4–9 / 3–7 / 2–4 с, пистолет 2–5 / 2–4 / 1–2 с. Стадии сжимаются,
если слот раунда плотный; сумма не выходит за лимит, зазор между выстрелами
≥5 с, ISSF-таймер не нарушается. Стадия видна на табло и уходит в снимок
состояния (`botst`) — гости прошлых версий её игнорируют.

## 3–5. Правила, протоколы, терминология

**Терминология — СДЕЛАНО** (`29d218b`): помощник вместо «Судья», главный судья
отделён от тренера, жюри подписано «Жюри», спортсмен единообразно, подписи
приглашений исправлены.

**Найдено и НЕ исправлено (требует решения по ISSF-редакции):**

| Что | Сейчас | По правилам |
|---|---|---|
| Ничья при двойном выбывании | countback по последним сериям | перестрелка (одиночные выстрелы) — **сверить 6.23** |
| Окно «отметить выстрел» после «Стоп» | 10 с (и +5 с в сети) | выстрел после «Стоп» не засчитывается; окно — только как компенсация сетевой задержки |
| Жеребьёвка стартовых номеров | порядок создания | жеребьёвка перед финалом |
| Живой рейтинг | по среднему выстрелу | по сумме на контрольной точке |
| Пауза | без ограничения числа/времени | только по решению судьи/при неисправности |
| Роль «жюри» в данных | `role == coach` | отдельная роль или флаг |

## 6. Публичные финалы и трансляция

- Публичный финал есть: таблица `finals_board` (anon-readable), подключение
  зрителя через RPC-секрет канала, лимит зрителей 10–150 (проверяется в
  памяти хоста, не на сервере).
- **Трансляции наружу нет**: нет read-only веб-страницы, share-ссылки и реле.
  Простой путь — страница, читающая `finals_board` + WebSocket на тот же
  канал с anon-ключом, плюс серверный лимит зрителей. Нужно решение.

## 7. Присоединение участников

Работает через `nexus-final:<base64>` в чате/коде, TTL 12 ч, токен без
привязки к устройству: один токен можно использовать с нескольких устройств,
дублей в списке нет (строка обновляется). Перезапуск приложения хостом
теряет финал (токены в памяти) — кандидат на сохранение.

## 8. Горизонтальный режим — СДЕЛАНО

Комнатный финал получил wide-раскладку (таблица слева, мишени справа, у
зрителя сетка 3 колонки), проверено на 640×360 и 1280×800 без переполнений.
Соло-финал и история упражнения — уже с wide, теперь с панелью SIUS.

## 9. Сохранение и публикация

- Локально — `finals_runs` (полный протокол с координатами).
- Публично — `finals_champions` после подписи тренера/самопроверки; жалобы и
  апелляции есть.
- Не сделано: полный протокол финала не передаётся тренеру (он видит только
  запрос на подпись), нет тренерской аналитики финалов.

## 10. Озвучка

Работает TTS (`FinalsAnnouncer`) + предгенерация mp3 своими ключами
(`VoicePacks`). Набор `Downloads\finals_voice` (3125 wav, 441 МБ, 14 языков)
не подключён: схема манифеста не совпадает с приложением, нужен импорт пака
(чтение манифеста, копирование в каталог приложения, выбор языка).

## 11. Инструкции для ИИ — СДЕЛАНО

`assets/ai/app_guide.md` (12 КБ) — разделы Supabase, Google Диск, мессенджер,
финалы, 3D-модели, PDF, задания, статистика. В промпт попадает только
релевантный раздел (≤1500 знаков); scope ослаблен: вопросы о функциях
приложения разрешены, оффтоп по-прежнему отклоняется. Дополнительно
подтягиваются `guide:*`-строки `table_docs` (≤3, по ключевым словам).
Прирост системного блока на app-вопросах +0.9–1.4 КБ (≈350 токенов).

## 12. ИИ меняет структуру приложения (идея) — ОТВЕТ

Технически возможно, но не сейчас: структура DSH-подобной гибкости требует
реестра плагинов/модулей, схемы прав и песочницы, а в приложении каждый экран
— скомпилированный Dart. Реальный промежуточный шаг — «данные вместо кода»:
плитки, порядок модулей, блоки статистики и формы графиков уже настраиваются
из базы; следующий уровень — хранимые описания экранов (JSON-схема + готовые
блоки), которые ИИ собирает и проверяет. Полная смена кода — отдельный проект
(загрузка плагинов, изоляция, ревью пользователем).

## Панель как SIUS (по фото владельца) — СДЕЛАНО

метка серии» с разделителями, крупно последний выстрел, `Σ 628.4 — 12`
(сумма и число «центральных» после тире), суммы серий; в пристрелке —

прочие 10.4 (**ориентировочно, ждут подтверждения**).
