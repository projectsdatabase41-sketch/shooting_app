# 04. Проверка базы: ошибка SQL

**Источник:** отзыв 19.11, 11:46 — «пишет, что не хватает каких-то таблиц, я
скопировал код и попробовал вставить снова, но получил ошибку
`ERROR: 42601: syntax error at or near "on"`, строка 1905:
`ALTER TABLE on ENABLE ROW LEVEL SECURITY;`».

## Что проверено

- Экран «Настройки → Данные и синхронизация → Проверка базы» копирует
  `lib/db/nexus_personal_db.sql` — 1887 строк.
- В нём нет строки `ALTER TABLE on ENABLE ROW LEVEL SECURITY`; все семь
  вхождений корректны (`alter table project_settings …`, `notes`, `keepalive_log`,
  `coach_chat` и три `execute format('alter table %I …')`).
- В `lib/db/puls_install.sql` и `lib/db/local_schema.sql` такой строки тоже нет.

Значит в SQL Editor попал старый или смешанный текст из буфера обмена: при
вставке поверх выделенного фрагмента Supabase склеивает строки, и имя таблицы
теряется — остаётся `ALTER TABLE on`.

## Что осталось

1. Получить от пользователя точный текст: скриншот экрана «Проверка базы» до
   копирования либо саму строку из SQL Editor вокруг 1905-й.
2. Если текст действительно из приложения — найти расхождение (возможно, в
   сборке на устройстве старый assets-файл, кэшированный при обновлении).
3. Дополнительно: перед копированием проверять целостность SQL (нет ли строк
   `alter table on`, нет ли обрыва в конце) и, если найдено, показывать
   предупреждение вместо копирования.

## Что уже сделано (20.11)

Экран «Проверка базы» теперь перечисляет, каких именно таблиц и функций не
хватает, и просит вставлять SQL целиком, заменяя прежний текст (`f2bdbf3`).

## Как проверить

Нажать «Скопировать SQL», вставить в пустой SQL Editor, запустить. Должно быть
«Success. No rows returned», после «Проверить снова» — «Всё на месте».
