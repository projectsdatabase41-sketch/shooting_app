# Puls для ИИ — как работать с приложением и его данными

Публичный документ: его читают персональные ИИ всех пользователей. В нём
НЕТ секретов, адресов чужих баз и личных данных — и быть не должно.
Каждая запись ниже — одна строка публичной таблицы инструкций
(`qwen_public_instructions`): «Название» → «Когда применять» → «Инструкция».
Проверено по коду приложения версии 0.2.0.

---

## 1. Puls: что это и как устроено

**Когда применять:** пользователь спрашивает, что за приложение, где что
лежит, или вы впервые готовите данные для Puls.

**Инструкция:**
Puls — приложение для спортивной пулевой стрельбы (Android, Windows, веб).
Записывает каждый выстрел КООРДИНАТАМИ пробоины в миллиметрах, а не
только очками: из координат считаются очки, средняя точка попадания,
кучность и направление увода.
- Роли: **спортсмен** (ведёт тренировки) и **тренер** (смотрит дневник
  спортсмена по выданному им токену, комментирует). Режим переключается в
  настройках.
- Вкладки спортсмена: Упражнения · Мишень · Статистика · Ассистент ·
  Настройки, плюс собственные плитки «Сервисы». Тренера: Дневник ·
  Спортсмены · Статистика · Ассистент · Настройки. Состав вкладок
  пользователь настраивает сам (кроме «Мишени» и «Настроек» — их скрыть
  нельзя).
- Приложение стартует пустым: ни демо-упражнений, ни демо-тренировок.
- Мишени (код → что это): `rifle_10m` — № 8, пневм. винтовка 10 м, калибр
  4.5; `pistol_10m` — № 9, пневм. пистолет 10 м, 4.5; `rifle_50m` — № 7,
  м/к винтовка 50 м, 5.6; `pistol_25m` — № 4, пистолет 25 м, 5.6.
  Других кодов приложение не знает.
- Приложение не оценивает «хорошо/плохо» и не мешает стрелять: все
  выстрелы записываются всегда.

## 2. Puls: настройки приложения (где что искать)

**Когда применять:** пользователь спрашивает «где это включить/поменять».

**Инструкция:** вкладка «Настройки» — разделы:
- **Внешний вид:** язык; «Цветовые настройки» — тема (система/светлая/
  тёмная), готовые пресеты цветов приложения (Графит, Хаки, Ночь, Кофе,
  Светлый, Мята), свои цвета фона/кнопок/текста, цвета мишени и пробоин
  (выбор круговой палитрой или кодом HEX).
- **ИИ Ассистент:** ключ OpenRouter (свой; без него работает встроенный
  тестовый), цепочка моделей, справочные материалы.
- **Данные и синхронизация:** импорт и экспорт тренировок, облако
  (синхронизация), выдача доступа тренеру.
- **Рабочие пространства:** какие вкладки показывать и в каком порядке;
  режим «плитки» или «страницы».
- **Сервисы:** свои плитки на главном экране — подключение внешнего
  источника (ссылка, JSON, Airtable, Supabase, заметки…).
- **Режим тренера:** переключение спортсмен/тренер.
- **Учётная запись:** подключение к СВОЕЙ базе Supabase (адрес проекта +
  публичный ключ, вход по почте и паролю), «Проверить базу», выбор
  «Таблиц для ИИ» — какие таблицы своей базы ассистент может читать.
Пользователь сам вводит свои ключи в настройках. Никогда не просите его
присылать пароли или секретные ключи вам в чат.

## 3. Puls: где живут данные и как работает облако

**Когда применять:** вопросы «где мои данные», «пропадёт ли при
переустановке», «как перенести на другой телефон».

**Инструкция:**
- Основное хранилище — локальная база на устройстве (в веб-версии — в
  браузере: очистка данных сайта = потеря данных).
- Облако необязательно: пользователь подключает СВОЙ проект Supabase, и
  завершённые тренировки синхронизируются туда («Настройки → Данные и
  синхронизация → Синхронизировать»). Один проект — один спортсмен.
- Тренер получает доступ по токену, который выдаёт спортсмен; токен
  можно отозвать — доступ прекращается сразу.
- Что синхронизируется: тренировки, упражнения, выстрелы, комментарии.
  Пауза-интервалы и «избранное» — только локально.

## 4. Puls: как подготовить тренировки для импорта (ГЛАВНЫЙ способ)

**Когда применять:** пользователь прислал результат тренировки — PDF,
фото, скриншот, таблицу, текст — в любом виде, и хочет увидеть его в
приложении.

**Инструкция:** подготовьте файл `.json` и попросите пользователя
загрузить его: **Настройки → Данные и синхронизация → Импорт тренировок →
«Выбрать файл»**. Перед записью приложение показывает, что будет
добавлено; пользователь нажимает «Добавить N в базу». Пароли и доступ к
базе вам НЕ нужны.

Формат (версия 1):
```json
{
  "format": "shooting_app.import",
  "version": 1,
  "source": "откуда данные, например: фото протокола / SCATT PDF",
  "sessions": [
    {
      "started_at": "2026-09-05T18:30:00+05:00",
      "finished_at": "2026-09-05T19:20:00+05:00",
      "exercise": {
        "name": "ВП-60",
        "target_face_code": "rifle_10m",
        "total_shots": 60,
        "series_size": 10
      },
      "extra": {"event": {"kind": "training"}},
      "shots": [
        {"n": 1, "series": 1, "x_mm": 0.8, "y_mm": -1.2, "score": 10.4},
        {"n": 2, "series": 1, "x_mm": -0.3, "y_mm": 0.5, "score": 10.7,
         "time": "2026-09-05T18:31:10+05:00", "counts": true}
      ]
    }
  ]
}
```
Обязательно: `format`, `version` (целое, сейчас 1), `sessions` (не пусто);
у тренировки — `started_at` (ISO 8601), блок `exercise` с
`target_face_code` (один из четырёх кодов из записи 1), непустой массив
`shots`; у выстрела — `x_mm`, `y_mm`, `score` (числа, `score` от 0 до
10.9). Необязательно: `finished_at`, `name`, `total_shots`, `series_size`,
`n` (номер, иначе по порядку), `series` (иначе 1), `time`, `counts`
(`false` = пристрелка, в сумму не идёт), `extra` (что угодно — показатели
прибора, разметка).
Свойства импорта, которые нужно знать:
- **Всё или ничего:** одна ошибка в файле — не добавится ничего, приложение
  покажет понятный текст ошибки («Тренировка 2: выстрел 5: результат 11.2
  вне шкалы»). Исправьте и загрузите заново.
- **Повторная загрузка того же файла создаёт дубликаты** (у каждой
  тренировки новый идентификатор). Не просите загружать один файл дважды.
- Результат берётся из файла КАК ЕСТЬ и по координатам не пересчитывается
  (прибор или протокол — источник истины).
- Упражнения не плодятся: совпадение по названию + мишени + размеру серии.

## 5. Puls: правила создания записей (что и как заполнять)

**Когда применять:** вы формируете файл импорта или запись в базу и
сомневаетесь в значениях.

**Инструкция:**
1. **Мишень известна заранее.** Спросите у пользователя, по какой мишени
   стрелял (или возьмите из названия упражнения). Не определяйте тип по
   картинке: снятая под углом мишень 10 м похожа на 50 м.
2. **Координаты:** начало — центр мишени, единицы — миллиметры, ось X
   вправо, ось Y **вверх**. Перевёрнутый знак Y зеркалит группу, а сумма
   очков при этом сходится — ошибку не видно. Сверьте 2–3 выстрела с
   картинкой (выше центра на бумаге → `y_mm > 0`).
3. **Откуда брать координаты (лестница точности):** (A) настоящие
   координаты из источника (векторные пробоины в PDF, CSV прибора) —
   берите как есть; (B) есть результат и направление — радиус считайте
   из результата, угол берите с картинки (формула:
   https://github.com/projectsdatabase41-sketch/shooting_app/blob/main/DATA-INGEST.md,
   раздел 6); (C) только результаты — `x_mm`/`y_mm` обязаны быть
   числами: поставьте `0` и в `extra` выстрела `{"coords":"unknown"}`, и
   СКАЖИТЕ пользователю, что точки на мишени условные. Не выдумывайте
   положение.
4. **Результат** записывайте как в источнике, с десятыми (10.6). Шкала
   0…10.9. Целые очки — это отбрасывание десятых у каждого выстрела.
5. **Пристрелка:** `counts: false` на самих выстрелах.
6. **Показатели прибора** (время прицеливания, устойчивость, скорость) —
   в `extra` выстрела структурой, под ключом с именем прибора:
   `{"scatt": {"aim_time_s": 18.4}}`. Не в текст комментария.
7. **Проверки до выдачи файла:** число выстрелов совпало с заявленным;
   сумма по каждой серии и общая совпала с итогом в источнике; номера
   выстрелов без дыр; результаты в 0…10.9. Не сошлось — не выдавайте
   файл молча, покажите пользователю расхождение.
8. **Не уверены — спросите.** Пропущенное поле лучше пустым, чем
   выдуманным. Не подгоняйте цифры под сумму.
9. Подписывайте `source` — откуда взяты данные (для разбора спорных случаев).

## 6. Puls: прямая запись в базу пользователя (запасной способ)

**Когда применять:** пользователь явно попросил записать тренировку
прямо в его базу Supabase, минуя файл импорта, и сам вошёл под своей
учётной записью в вашем сеансе.

**Инструкция:** это сложнее файла импорта и рискованнее — по умолчанию
используйте запись 4. Если всё же нужно:
- Писать в таблицы тренировок может только владелец базы (вход по почте и
  паролю → токен). Публичный ключ позволяет только читать инструкции.
  Ключ `service_role` никогда не запрашивайте и не используйте.
- Порядок из-за внешних ключей: `target_faces` (найти по `code`) →
  `exercise_templates` (искать по названию + мишени, не плодить) →
  `training_packages` (`package_status = 'completed'`, только такие
  приложение считает завершёнными) → `exercises` (ровно одна строка на
  тренировку, её `id` РАВЕН `id` пакета, иначе приложение не найдёт
  выстрелы) → `shots` (`exercise_id` = id пакета; `final_score`
  результат как есть; `shot_time_ms` — целое смещение от начала в
  миллисекундах или пусто).
- Разрешённые значения `source`/`coordinate_source` у выстрела: `pdf`,
  `photo`, `file_import` (плюс `manual`, `auto`, `manual_corrected`,
  `tap`, `score_angle` по смыслу); имя прибора туда не пишется — в `extra`.
- Идентификаторы детерминированные, вставка «игнорировать дубликаты»:
  повторный прогон не должен плодить строки.
- Подробная актуальная структура таблиц и правила лежат в самой базе
  пользователя: таблица `table_docs` (читается публичным ключом).
- После записи прочитайте данные обратно и покажите пользователю сводку
  (мишень, дата, число выстрелов, суммы) — пусть сверит в приложении.

## 7. Puls: встроенный ассистент — что он видит и умеет

**Когда применять:** вопросы «а ассистент в приложении это знает?»,
«как научить его читать мою таблицу».

**Инструкция:** ассистент внутри Puls отвечает по данным тренировок
пользователя и умеет строить графики. Он может читать справочные
таблицы: общую базу правил/книг и таблицы из СВОЕЙ базы пользователя,
которые тот подключил («Настройки → Учётная запись → Таблицы для ИИ»).
Только чтение: создавать таблицы и записывать данные ассистент не умеет.
Ищет по ключевым словам в текстовых колонках (`content`, `topic`,
`title`, `summary`, `description`), даты записей и текущее время
учитывает; очень длинные строки видит кусками до ~2000 символов. Помнит
прошлые разговоры кратко (сводки), если подключена облачная база.

## 8. Puls: правила безопасности для любого ИИ, работающего с Puls

**Когда применять:** всегда.

**Инструкция:**
- Не просите и не сохраняйте пароли, `service_role`, токены доступа
  тренера, ключи OpenRouter в чате и в общедоступных таблицах: публичную
  таблицу читает любой.
- Не удаляйте и не «чистите» чужие таблицы и права: они могут казаться
  лишними и быть нужными другим ИИ и приложению.
- Не пишите данные молча: сначала покажите пользователю, что именно
  запишете. Импорт через файл делает эту сверку сам.
- Для разбора фото и сканов используйте сильную модель с хорошим зрением
  и арифметикой; слабая ошибается тихо (знак оси Y, сдвиг кольца, потерянные
  десятые). Проверки из записи 5 обязательны для любой модели.
