## 2. Кнопка «+» в чат (`Кнопка + в чат.txt`) — брать частично

**Важно:** веер по дуге в чате уже пробовали и отказались — отзывы 05.11 и 16.11
попросили столбик ближе к пальцу. Сейчас `FanButton(vertical: true)` в
`chat_thread_screen.dart:2593`. Дугу не возвращать.

Из промпта берём только физику и микродвижения:
- поворот главной кнопки 0→45° (плюс становится крестиком) на spring;
- стаггер пунктов 0.05 с, подпись `x: 8→0` и opacity за 0.15 с (задержка +0.1 с);
- `scale` пункта 0.3→1, главной — hover 1.05 / tap 0.95.

Размеры (в промпте их нет, задаём сами): FAB 56, иконка 24 (stroke 2), пункт 40
с иконкой 20, подпись 13, зазор между пунктами 10, отступ от клавиатуры 12.
Spring: `SpringDescription.withDampingRatio(mass: 1, stiffness: 520, ratio: 0.78)`
для кнопки и `stiffness: 420, ratio: 0.72` для пунктов — числа 500/30 и 400/22 из
`motion` не переносятся один-в-один, подобран�� заново.

Состав пунктов оставить текущий (HD, кружок, фото/файл, большой файл, ИИ) —
в референсе четыре других (Camera/Image/File/Edit), они не про этот чат.

Web: 6 пунктов + подписи, теней на анимируемых элементах не вешать, блюра нет —
на CanvasKit это дёшево. `AnimatePresence` заменяется одним
`AnimationController` + `ReverseAnimation`, список снимается в `completed`.

## 3. Peak Chart (`Пропт статистики.txt`) — брать целиком, но поле запечь

Что переносим: карточка 540×696 единиц (ratio 1.289), сетка 13×12 без подписей,
сплайн Стеффена (без перелёта), затухание линии от пика по `exp(-(|d|/108)^1.44)`,

Что НЕ переносим: per-pixel расчёт glow-поля (6 гауссовых шейдов × 3 кромки на
пиксель, ~1.26 млн пикселей и ~4 млн `erf` на кадр при смене размера).
Поле статичное — его надо один раз превратить в `ui.Image` и кэшировать
`Map<int, ui.Image>` по ширине, либо запечь PNG в `assets/bg/peak_{dark,light}.webp`

расчёта на старте, ~5 МБ памяти на две картинки вместо ~17 МБ полотен.

Размеры: ширина = ширина карточки, высота = ширина × 1.289. Телефон 361 → 465,
десктоп 449 → 579 (5 колонок из 12 при контенте 1100). Радиус 16, внутренняя

(десктоп), число 89.2u → 60 / 74, caption 11.6u → 10 / 12. Ниже 11 px не опускать.

## 4. AnalyticsBento (`Кнопка статистики тренировок.txt`) — брать 4 карточки

Состав: линия с заливкой, «волны» двух серий, treemap, радар. Все четыре —
свой `CustomPainter` в духе `lib/painters/analytics_painters.dart` (цвета
параметрами, без `Theme.of` внутри painter'а).

Сетка и размеры для веба (контент приложения ограничен 1100 px, `main.dart:577`):

| Ширина окна | Контент | Колонок | Раскладка |
|---|---|---|---|
| ≤ 700 (телефон) | 100% − 32 | 1 | карточки друг под другом, gap 12 |
| 701–1023 (планшет) | 100% − 40 | 1 | то же, gap 16 |
| ≥ 1024 (десктоп) | ≤ 1100 | 2×2 | 5+7 / 7+5, gap 16 |

При 1100: колонка 77 px, 5 колонок = 449, 7 = 635. При 992: 68 / 404 / 572.
Высоты графиков: линия 120 (телефон) / 140 (десктоп), волны 128/144,
treemap 260/300, радар 320 квадрат, `max-width 360`.

Математика переносится как есть: шаг оси `10^floor(log10(span/4))` из
`[1, 2, 2.5, 5, 10]`, Catmull-Rom с `k = 0.18`, squarify для treemap,
радар с нормировкой `0.42…1` и рядом Фурье `K = min(5, N/2)`, 180 сегментов.

Цвета серий: 4 группы treemap — производные от палитры (сланец, янтарь, зелёный,
терракота), без кислотных `#7CFF5B`/`#8B3DFF`.

Web: «волны» в оригинале анимируются бесконечно на `requestAnimationFrame` —
на вебе либо 30 fps, либо остановка через 20 с, либо статичный кадр при
`prefers-reduced-motion`. Tooltip — свой `OverlayEntry`, без `BackdropFilter`
(полупрозрачная заливка `surfaceContainerHighest` с alpha .95). Цифры в
`AnimatedPositioned` по 4 параметрам на плитку treemap (до 11 плиток).

## 5. Glass dashboard (`Пропт финансовой статистики.txt`) — только стекло и ползунки

Это финансовый дашборд (баланс, транзакции, цели, CSV). Финансовые данные в
приложении ни при чём — переносить экран целиком нельзя. Полезное:

- параметры стекла: blur 0–40, opacity 0.08–0.9, saturation 0.5–2, edge light
  0–1, tint — и пресеты Clear/Frosted/Solid. В приложении уже есть
  `GlassTheme` (`lib/theme/glass.dart`: `buttonBlur 12`, `windowBlur 18`,
  `alpha`, «Эконом»). Значения промпта → в настройки «Внешний вид» как
  расширение существующих, а не второй механизм;
- пять «стеклянных» слоёв одновременно (topbar, main, рейл, dock, панель) — так
  делать нельзя: на CanvasKit каждый `BackdropFilter` это `saveLayer`, а
  `BackdropFilter` при прозрачном фоне ещё и требует перерисовки фона. Бюджет:
  **не больше трёх** на экран, sigma ≤ 20, sigma менять только по отпусканию
  ползунка, `RepaintBoundary` на статичные панели, `ClipRRect` обязателен;
- `saturate()` аналога нет: `ColorFilter.matrix` с матрицей насыщенности или
  отказ от насыщенности (проще — отказ);
- `inset box-shadow` во Flutter нет: 1 px внутренняя кромка рисуется градиентной
  обводкой (`DecoratedBox` + `BoxDecoration(gradient:)`) или `CustomPaint`.

Вывод: из этого промпта берём настройки стекла и приёмы кромок, экран — нет.

## 6. Расчёт под веб (общий)

- `dpr` ограничить 2 (`min(devicePixelRatio, 2)`), иначе полотна крупнее памяти.
- Контент ≤ 1100, боковые отступы 16 (телефон) / 20 (иначе).
- Не больше 3 `BackdropFilter` на экран, sigma ≤ 20, без анимации sigma.
- Не больше 2 постоянных анимаций одновременно; «дыхание» и бесконечность — off.
- Тяжёлые растры (glow-поле) — запекать в `ui.Image`/PNG, а не считать в кадре.
- `Path`/`PathMetric` — в кэш по ключу (ширина, тема), пересчёт только при смене.
- Шрифт только Roboto (вшит); `google_fonts` и Geist не подключать.
- Числа — `FontFeature.tabularFigures()`, чтобы не дёргались при count-up.
- Память: peak-картинки ~5 МБ, полотна treemap/радара ≤ 3 МБ на экран.
